# RPM Club

Работающий full-stack проект: Telegram Mini App, админка, программа лояльности, CSV/XLSX и очередь уведомлений. Next.js + TypeScript + PostgreSQL.

## Локальный запуск

Нужны Node.js 22.16+ и запущенный Docker Desktop.

```powershell
npm ci
npm run setup:local
npm run dev
```

Открыть **http://127.0.0.1:3001/preview**. Доступны клуб, админ, менеджер и просмотр. Эти входы работают только локально в development при `LOCAL_PREVIEW=1`. Формы сохраняют данные в PostgreSQL; обновление страницы их не сбрасывает.

После перезагрузки компьютера: открыть Docker Desktop, дождаться запуска движка, затем в папке проекта выполнить:

```powershell
docker start rpm-club-db
npm run dev
```

Окно с `npm run dev` должно оставаться работающим. Одна ссылка не запускает сервер. Для повторного старта установка зависимостей и seed не нужны. Если `/preview` открывается, но вход не работает, проверить `http://127.0.0.1:3001/api/ready` и состояние Docker.

В текущей среде база и `.env.local` уже подготовлены. `setup:local` сохраняет настройки, применяет миграции и идемпотентный seed. Секреты не выводятся. База слушает только `127.0.0.1:55432`; контейнер — `rpm-club-db`, volume — `rpm-club-data`. Остановка: `docker stop rpm-club-db`.

Seed: четыре синтетических участника. Исходно Роман — BLACK / 428 500 ₽ / 8 420 Bonus, Анна — MEMBER / 0. В текущей базе дополнительно сохранена проверочная аренда Романа 35 000 ₽: итог **463 500 ₽ / 9 820 Bonus**. Повтор seed не стирает операции.

## Проверки

```powershell
npm run typecheck
npm run lint
npm test
npm run test:integration
npm run build
```

`npm test` запускает unit-тесты; без тестового URL интеграционные файлы явно пропускаются. `test:integration` использует только отдельную `rpm_club_test`, применяет миграции и запускает все тесты последовательно. Провайдеры заменены тестовыми ответами; реальных отправок нет.

## Реализовано

- Программа из пяти или шести уровней, скидки либо cashback по редакции программы, цвета и названия карт, точные суммы, Bonus ledger/lots, FEFO, срок действия, списания, отмены, дефицит, сохранение статуса, рефералы.
- Telegram HMAC, свой контакт, версии согласий, серверные сессии, роли и MFA с настройкой при первом входе администратора.
- Главная, Club, история, профиль, QR, предложения; админка, фильтры, импорт с preview/возобновлением, настройки с preview порогов, аудит, сотрудники.
- Автопарк, заявки с расчётом скидки и подтверждением менеджера, маршруты, Wiki/FAQ/условия, настройка пяти типов автоматических уведомлений. См. [правки сентября](docs/SEPTEMBER-CHANGES.md) для бизнес-настроек и планировщика.
- Очередь Telegram-уведомлений с повторными попытками и защитой от одновременной обработки.
- Миграции, bootstrap, CI, шаблон импорта и инструкции эксплуатации.

## Перед реальным запуском

Нужны аккаунты и ключи RPM: Telegram, Supabase Auth/Storage и публичный HTTPS-домен. Юридические тексты seed — тестовые. Реальная проверка Telegram, iPhone/Android, CRM-файла, backup/restore и нагрузки ещё нужна; локальная сборка не заменяет эту приёмку.

Worker выполняет реальные отправки при наличии credentials. В опубликованном проекте Supabase cron вызывает защищённый `/api/internal/jobs` раз в минуту; при отдельной установке нужно настроить планировщик либо запускать `npm run jobs`. Production-входы без Telegram и синтетический seed отключены.
