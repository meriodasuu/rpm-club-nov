# Выпуск на существующем сервере RPM Rent

Проверка 25.09.2026: Ubuntu 26.04 x86_64, 2 CPU, 1962 MiB RAM, swap 2 GiB, диск 38 GiB. Сайт RPM Rent, PostgreSQL и его Telegram-сервис уже работают в Docker. HTTPS обслуживает `rpm-rent-caddy-1` в сети `rpm-rent_web`; nginx и отдельный systemd worker здесь не устанавливаются.

RPM Club использует отдельный Compose-проект `rpm-club`, контейнер `app`, alias `rpm-club` в сети прокси. Лимит RAM 768 MiB, RAM+swap 1024 MiB, CPU 1. Порт 3001 опубликован только на loopback. Файловая система контейнера read-only; временные каталоги ограничены. Supabase PostgreSQL/Auth/Storage остаются внешними. Планировщик — прежний Supabase Cron; вторую копию worker не запускать.

## Сборка

Исходники выпуска: `/opt/rpm-club/releases/<release>`. Передавать только файлы проекта, без `.env*`, `.local`, документов и Windows `node_modules/.next`.

Linux `node_modules` и `.next` создаются в отдельном контейнере официального Node 22. Для этой машины сборка ограничена 896 MiB RAM, RAM+swap 1792 MiB, одним CPU, Node heap 640 MiB. На работающем сайте проверять свободную память и ответы HTTP во время сборки. Удаление cache/образов других приложений не требуется.

После успешных `npm ci --include=dev --no-audit --no-fund` и `npm run build` собрать `deploy/Dockerfile.runtime` из каталога выпуска. `NODE_IMAGE` фиксировать digest проверенного базового образа. Production-секреты передаются только при запуске; в build context и image их нет.

## Запуск и переключение

1. `/etc/rpm-club.env`: root:root 0600, по одной `KEY=value` на строку без внешних кавычек. Compose читает `format: raw`, поэтому `$` в секретах не интерполируется. Сохранить действующие ключи шифрования, сессий, webhook и cron. Preflight должен пройти полностью, включая Storage key.
2. Задать `RPM_CLUB_IMAGE=rpm-club:<release>` и выполнить `sudo --preserve-env=RPM_CLUB_IMAGE docker compose -f deploy/compose.vps.yml up -d`. Проверить healthcheck, `http://127.0.0.1:3001/api/ready` и доступ к Supabase. Не открывать порт 3001 в firewall.
3. После настройки DNS согласованного адреса установить его в `APP_URL`, пересоздать только Club. Скопировать текущий `/opt/rpm-rent/deploy/Caddyfile` в приватный каталог backup; добавить блок `deploy/Caddyfile.club`, предварительно проверив hostname. Не заменять правила основного сайта.
4. Проверить Caddyfile через `caddy validate`. Существующий Caddy работает с `admin off`, поэтому применение требует краткого перезапуска только `rpm-rent-caddy-1`. Проверить TLS, Club и основной сайт сразу после применения; при ошибке восстановить прежний Caddyfile.
5. Только после исправного HTTPS переключить webhook (без удаления pending updates), Main Mini App, общее и персональное меню бота. Обновить origin Supabase Cron, сохранить secret. Проверить адреса чтением, успешный вызов worker и свежий heartbeat.
6. Пройти прикладную приёмку из `README.md`. Не считать HTTP 200 подтверждением наполнения автопарка, юридических документов или настройки программы.

## Резервирование и откат

Перед переключением сохранить данные только таблиц RPM Club через `pg_dump --data-only --enable-row-security`, TLS verify-full и доверенный CA. Политики runtime-роли должны разрешать все строки этих таблиц; проверить это перед копированием. Общая Supabase-схема содержит и другие приложения — не включать их таблицы в копию Club. Схема Club восстанавливается из 15 миграций соответствующего выпуска, данные — через `pg_restore --disable-triggers --single-transaction --exit-on-error` в изолированной базе от её администратора. Перед импортом в этой одноразовой базе удалить только данные, добавленные миграциями. Эти команды восстановления нельзя выполнять в production.

Dump содержит данные клиентов: хранить в `/opt/rpm-club/backups` с ограниченными правами, не включать в Git. Это копия приложения; Auth/Storage и независимую внешнюю копию проверять отдельно. Проверку восстановления выполнять в изолированном контейнере без сети и без действующих ключей Telegram.

При неудачном первом переключении вернуть сохранённые адреса бота/cron и Caddyfile, остановить только Compose-проект `rpm-club`. Действующие данные Supabase не откатывать. Для следующих выпусков сохранять предыдущий image tag и запускать его при откате кода.

Факт переключения, адрес и результаты проверки фиксируются после выполнения; эта инструкция сама по себе не означает, что перенос завершён.
