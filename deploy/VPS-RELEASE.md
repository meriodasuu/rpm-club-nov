# Выпуск RPM Club на VPS

Целевая схема: Next.js 16 / Node.js 22, PostgreSQL 17, локальные изображения и отдельный worker. Внешние Auth/Storage и облачный планировщик приложению не нужны. Вход сотрудников — Telegram + TOTP, данные и зашифрованные настройки MFA лежат в PostgreSQL.

## Изоляция

На VPS 91.222.239.130 уже работает RPM Rent. Club использует отдельный Compose-проект `rpm-club` и отдельную базу `rpm_club`. Существующую БД RPM Rent не менять.

- `app`: 512 MiB RAM, порт только `127.0.0.1:3001`; Caddy обращается к alias `rpm-club`.
- `db`: 256 MiB RAM, PostgreSQL не публикует порт и подключён только к внутренней сети `rpm-club_backend`.
- `worker`: 224 MiB RAM, приватная сеть БД и отдельная dual-stack сеть для исходящих Telegram-запросов. Эта сеть также подключена к app: команды входа сотрудников отправляются из web-процесса. На данном VPS Telegram требует IPv6; для обоих Node-процессов установлен --dns-result-order=ipv6first.
- `telegram`: 144 MiB RAM, один экземпляр long polling через IPv6. Передаёт команды в app по приватной сети с webhook-секретом. Offset подтверждается только после HTTP 2xx; после рестарта непринятые команды возвращает Telegram, повторные записи отсеивает PostgreSQL. Постоянный файл offset не нужен. Не запускать второй poller или webhook одновременно.
- База: `/opt/rpm-club/data/postgres`; фото: `/opt/rpm-club/data/media` (UID/GID 1000, внутри app `/data/media`). Не удалять при обновлении контейнеров.
- `/etc/rpm-club.env` и `/etc/rpm-club-db.env`: root:root, 0600, формат KEY=value без кавычек. Пароли администратора БД и runtime-роли различаются. Приложение не получает пароль postgres.
- `DATABASE_PRIVATE_NETWORK=1` разрешает подключение без TLS только к имени `rpm-club-db`; другие удалённые базы требуют проверенного TLS.

## Сборка и миграции

1. Передать исходники выпуска без `.env`, `.local`, `.git`, пользовательских документов и локальных `node_modules` в `/opt/rpm-club/releases/<release>`.
2. Выполнить `npm ci --include=dev --no-audit --no-fund && npm run build` в Linux-контейнере Node.js 22. На этом VPS лимит сборщика: RAM 896 MiB, RAM+swap 1792 MiB, CPU 1, Node heap 640 MiB.
3. Создать образ через `docker build -f deploy/Dockerfile.runtime -t rpm-club:<release> .`. В образ не копировать секреты.
4. Первую БД создавать отдельно через `docker compose ... up -d db`. Создать ограниченную роль `rpm_club_app`. Миграции из `db/migrations` применяет администратор БД; `scripts/migrate.ts` ведёт журнал checksum. Затем выполнить `deploy/grants.sql` в выделенной Club БД.
5. При первичном переносе восстановить только 51 таблицу Club из исходной базы. Сначала проверить, что целевая БД новая и закрыта для пользователей. Seed-строки миграций убрать только в этой новой БД, затем импортировать data-only dump с `--disable-triggers --single-transaction --exit-on-error`. Сохранить имена/checksum всех 15 миграций. При обычном обновлении данные не очищать.
6. Сохранить действующие bot token, encryption key, session secret и идентификаторы пользователей/сотрудников. Проверить количество пользователей, аренд, сотрудников, записей MFA и миграций.
7. Задать `RPM_CLUB_IMAGE` и выполнить `docker compose -f /opt/rpm-club/deploy/compose.vps.yml up -d app`. Проверить `/api/ready`, загрузку и чтение фото, сохранность после перезапуска, роли и MFA.

## Переключение трафика

1. DNS A `club.rpm-rent.ru` → `91.222.239.130`. Отдельная покупка поддомена не нужна.
2. До окончательного снимка остановить приём записей старым приложением и прежний планировщик. Снять свежую копию Club и сверить/восстановить её до открытия новой базы. Не допускать одновременные записи в две базы.
3. В `/etc/rpm-club.env` установить `APP_URL=https://club.rpm-rent.ru` и `VERCEL=0`.
4. Сохранить `/opt/rpm-rent/deploy/Caddyfile`, добавить блок `deploy/Caddyfile.club`, проверить конфигурацию. У текущего Caddy `admin off`, поэтому требуется краткий restart только `rpm-rent-caddy-1`. Проверить оба сайта, сертификат и `/api/ready` через HTTPS.
5. На этом VPS входящий Telegram webhook по IPv4 не достигает сервера. Используется `TELEGRAM_UPDATES_MODE=polling` (задан в Compose). Запустить из app `node --import tsx scripts/telegram-setup.ts --apply`: скрипт проверяет бота и текущий адрес, отключает только совпадающий webhook с `drop_pending_updates=false` и обновляет общее меню. Персональные меню и Main Mini App также должны вести на `/onboarding` нового домена. Проверить настройки через `--check`. Старое приложение закрыть для записи и отправок.
6. Только после остановки старого планировщика включить `docker compose ... --profile worker up -d worker telegram`. Проверить оба heartbeat, ошибки очереди и доставку согласованному тестовому пользователю. Контейнер telegram при старте только проверяет конфигурацию, сам webhook не удаляет. В случае повторяющихся ошибок автоматически перезапускается с сохранением очереди Telegram.

Текущее состояние выпуска и проверки зафиксированы в [VPS-STATE.md](VPS-STATE.md). При последующих обновлениях не повторять первичный импорт и не очищать актуальную базу.

## Резервные копии и откат

`deploy/backup.sh` сохраняет БД, изображения и секреты в приватный каталог `/opt/rpm-club/backups/local`, хранение 14 суток. Установить скрипт и systemd backup service/timer, выполнить первую копию и восстановить её в отдельную тестовую БД без worker. Копия на том же диске не защищает от потери VPS: внешнее защищённое хранилище подключается отдельно.

Перед каждым обновлением сохранить резервную копию и предыдущий image tag. Для отката кода запустить совместимый предыдущий образ с той же актуальной PostgreSQL БД. Не возвращать старый dump поверх новых аренд. После переключения на VPS старый Vercel с прежней базой не является безопасным откатом: сначала нужен согласованный перенос новых данных или подключение к актуальной БД.

## Приёмка

Проверить в Telegram: вход, контакт, согласия, скидочную карту, заявку с оплатой на месте, обработку менеджером, реферальную награду и уведомления. Проверить лимиты памяти/диск, очередь, загрузку медиа и восстановление резервной копии. Каталог, юридические тексты, шесть уровней и реферальные условия должны быть заполнены заказчиком перед открытием клиентам.
