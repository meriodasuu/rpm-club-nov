# Core contract

`src/lib/db/index.ts`: `Db { query<T>(sql:string, values?:unknown[]):Promise<T[]> }`; exports `query`, `transaction<T>((tx:Db)=>Promise<T>)`, `closePool`. PostgreSQL bigint values are decimal **strings**, monetary amounts in kopecks and Bonus in whole units.

`src/lib/loyalty/index.ts` exports all functions below. Economic commands are atomic, audited, and outboxed; referral binding writes its audit in the binding transaction. Actor is `{id:string, role:'admin'|'manager'|'integration'|'system'}` (id is text, including service names). Commands take `(input, actor)`; only the explicitly exported referral composition helper accepts `Db`. Economic command inputs require an idempotency key; referral binding instead enforces one binding per referred user. Integration actors may call `processRental`, `adjustRental`, `cancelRental` only for their source: trusted actor id `integration:rpm` authorizes `source='rpm'`. Manual Bonus commands remain forbidden to integration; publication and tier changes require admin/system. Read functions assume the caller has already authorized access to the requested user.

* `processRental(input: RentalInput, actor): Promise<RentalResult>`; alias `processCompletedRental`. Input: `userId`, `externalRentalId`, `carName`, `startDate`, `endDate`, `amountKopecks:string`, `status:'completed'|'in_progress'|'cancelled'`, `paymentStatus:'paid'|'unpaid'|'partial'|'refunded'`, `qualifiedAt?:string`, `source?:string`, `mode?:'historical'|'operational'`, `idempotencyKey`, `reason?:string`, `importBatchId?:string`, `programVersionId?:string`. Result `{status:'processed'|'duplicate', rentalId, bonus:string, snapshot:AccountSnapshot}`; conflicting external ID or idempotency payload throws `LoyaltyError` with `.code` and `.status`.
* `creditBonus({userId,amount:string,expiresAt?:string,reason,idempotencyKey,type?:'manual_credit'}, actor)` → `{transactionId,snapshot}`. `opening_balance` requires an explicit expiry; already expired imported credit creates matching expiration atomically. Ordinary manual credit requires a future expiry.
* `debitBonus({userId,amount:string,type:'manual_debit'|'rental_payment',externalRentalId?:string,eligiblePriceKopecks?:string,reason,idempotencyKey},actor)` → `{transactionId,snapshot}`.
* `reverseTransaction({transactionId,reason,idempotencyKey},actor)` → `{transactionId,snapshot}`. Full unreversed operation reversal; repeat of same key safe.
* `adjustRental({rentalId,amountKopecks:string,reason,idempotencyKey},actor)` → `{rentalId,snapshot}`.
* `cancelRental({rentalId,reason,idempotencyKey},actor)` → `{rentalId,snapshot}`; reverses cashback, both referral rewards and linked redemptions atomically.
* `changeTier({userId,tier:TierCode|null,reason,idempotencyKey},actor)` → AccountSnapshot; admin only, null removes override without lowering achieved tier.
* `publishProgram({rewardMode?:'cashback'|'discount',tiers:TierRule[],redemptionLimitBps:number,expiryDays:number,referrerReward:string,referredReward:string,programStartsAt:string,reason,idempotencyKey},actor)` → Program; admin only. TierRule `{code,thresholdKopecks:string,rateBps:number,benefits:string[],displayName?:string,color?:'bronze'|'silver'|'gold'|'diamond'|'red'|'black'}`. Five existing levels remain valid; PLATINUM can be published between BLACK and RED. A published level cannot be removed. `rateBps` means cashback or discount depending on rewardMode; discount programs never accrue rental cashback. Publishes immutable version; `recalculateTiers()` upgrades accounts when their calculated tier changes. Snapshot additionally exposes `discount_rate_bps`.
* `bindReferral({userId,code},actor)` → `{status:string}`; invoke before activation after verified contact. `retryReferrals()` retries held qualified referrals once.
* `bindReferralInTransaction(tx:Db,{userId,code},actor)` shares the caller's transaction for atomic activation/consents/referral. Call before setting `member_since`. It locks both accounts; avoid acquiring the referred account alone beforehand in a conflicting order.
* `getAccountSnapshot(userId):Promise<AccountSnapshot>` performs due expiry under account lock. Snapshot `{user: {id,name,phone,telegram_id,telegram_username,public_member_id,referral_code,status,marketing_consent,created_at}, tier:TierCode, calculated_tier:TierCode, achieved_tier:TierCode, manual_override:TierCode|null, total_rental_amount:string, bonus_available:string, bonus_pending:string, bonus_debt:string, account_version:string, member_since:string|null, next_tier:TierCode|null, remaining_amount:string|null, progress_percent:number, cashback_rate_bps:number, benefits:string[], program:Program}`.
* `getProgram():Promise<Program>`; Program `{id,version:number,tiers:TierRule[],redemptionLimitBps,expiryDays,referrerReward,referredReward,programStartsAt}`.
* `getHistory(userId,kind:'rentals'|'bonus',limit?:number,cursor?:string):Promise<{items:Record<string,unknown>[],nextCursor:string|null}>`.
* `expireBonuses(limit?:number):Promise<number>`, `reconcileAccounts():Promise<{userId:string,expected:string,actual:string}[]>`.
* `recalculateTiers({limit?:number,cursor?:string|null,programVersionId?:string}={}):Promise<{processed:number,changed:number,nextCursor:string|null,done:boolean}>`. Default limit 50, maximum 100; cursor is the last processed user UUID. A supplied program version fixes the thresholds for that pass. Achieved tiers never decrease. Each account uses its own transaction and 2-second lock timeout; retry after a failure is safe. An empty final page returns done=true. Callers must continue while done=false.
* Pure `parseRubles(value:string):string`, `calculateTier(amount:string|bigint,tiers?:TierRule[]):TierCode`, `calculateRentalBonus(amount:string|bigint,rateBps:number):string`, `calculateTierProgress(amount:string|bigint,tier:TierCode,tiers?:TierRule[])`; `DEFAULT_TIERS`, `TIER_CODES` exported.

Qualification defaults: `resolveQualifiedAt(endDate,mode,qualifiedAt?,confirmedAt?:Date)` preserves an explicit timestamp. Without one, historical input and past operational dates use the end of that date in Moscow (`20:59:59.999Z`). An operational rental ending today uses actual confirmation time. Future completion remains rejected. Generated defaults do not vary the normalized payload hash on retries; the first stored timestamp remains unchanged for duplicates. For unpaid → adjustment → paid, original input identity/amount remains immutable, but first qualification applies `current_amount_kopecks`, including prior adjustments.

Expiry and lot eligibility use one PostgreSQL wall-clock timestamp captured after all account locks, refreshed immediately before spending. Snapshot reads expire due lots after obtaining their account lock. A spend can never create debt when its available lots become insufficient.

Maintenance integration: `src/lib/jobs/index.ts` exports `processProgramRecalculations(limit=50,eventId?:string)`. It handles one publication page, serializes workers, saves `payload.recalculateCursor`, and marks `expanded_at` only when done=true. The usual maintenance call processes 50 accounts. A crash before saving a cursor replays a safe page; provider delivery code remains unchanged.

## Shared tables

Migration SQL is authoritative. `users`: UUID id default, name, phone nullable unique, telegram_id bigint nullable unique, telegram_username, crm_customer_id, public_member_id random text, referral_code random text, status `pending|active|blocked`, marketing_consent boolean, telegram_reachable boolean, created_at/updated_at. `loyalty_accounts`: user_id PK, calculated_tier/achieved_tier/manual_override text codes, total_rental_amount/bonus_available/bonus_pending/bonus_debt/account_version bigint, member_since.

`program_versions`: id uuid, version integer unique, tiers jsonb (`TierRule[]`), redemption_limit_bps integer, expiry_days integer, referrer_reward/referred_reward bigint, program_starts_at timestamptz, **effective_at** timestamptz, published_by text. There is no `published_at` column on this table. `loyalty_tiers`: code PK, rank unique, name. `tier_benefits`: id, tier_id referencing tier code, title, description, sort_order, version. `tier_events`: id,user_id,from_tier,to_tier,reason,rental_id,program_version_id,actor_id,created_at.

`rentals`: id,external_rental_id unique,user_id,source,car_name,start_date,end_date,amount_kopecks (original),current_amount_kopecks,status,payment_status,qualified_at,processed_at,program_version_id,applied_rate_bps,import_batch_id,payload_hash,mode,is_qualified,net_cashback,cancelled_at,created_at. `rental_adjustments`: id,rental_id,operation_key unique,before_amount,after_amount,before_status,after_status,reason,actor_id,created_at. `redemption_references`: external_rental_id PK,user_id,eligible_price_kopecks. `customer_external_identities`: id,source,crm_customer_id,user_id, unique(source,crm_customer_id).

`bonus_transactions`: id,user_id,rental_id,external_rental_id,type,amount (signed bigint Bonus),posting_state,business_key unique,reverses_id,reason,actor_id,program_version_id,created_at. `bonus_lots`: id,user_id,credit_transaction_id unique,issued_amount,remaining_amount,available_at,expires_at. `bonus_allocations`: id,transaction_id,lot_id,amount,kind `spend|reversal|debt_offset|expiration|restore`,created_at, unique(transaction_id,lot_id,kind).

`referrals`: id,**referrer_id**,**referred_id** unique,code_snapshot,status `bound|qualified|rewarded|ineligible|reversed`,qualifying_rental_id,referrer_reward,referred_reward,program_version_id,reason,rewarded_at,created_at. A held reward uses `status='qualified'` and `reason='blocked_hold'`; there is no separate `hold` status. `referral_rewards`: referral_id,beneficiary_user_id,transaction_id unique, PK(referral_id,beneficiary_user_id). No `referrer_user_id` or `referred_user_id` columns exist. `idempotency_requests`: scope,key,payload_hash,result jsonb,created_at, PK(scope,key).

`miniapp_sessions`: id uuid, token_hash unique, user_id nullable, telegram_id bigint, telegram_profile jsonb default `{}`, expires_at, revoked_at, created_at. `contact_requests`: id uuid, session_id FK, telegram_id bigint, expires_at, consumed_at, phone. `telegram_updates`: update_id bigint PK, created_at. `admin_memberships`: id uuid, auth_user_id uuid unique (Supabase Auth reference logical because vanilla PG), email, name, role `admin|manager|viewer`, active, created_at. `staff_sessions`: id uuid,token_hash,membership_id,expires_at,revoked_at,created_at. `legal_documents`: id, type `rules|privacy|personal-data`, version text, title, body, published_at, unique(type,version). `consent_acceptances`: id,user_id,document_id,accepted_at,source, unique(user_id,document_id). `marketing_consents`: id,user_id,granted,created_at,source. `rate_limits`: key text PK,count integer,window_start timestamptz.

`offers`: id, title, subtitle, car_name, image_url, description, old_price/new_price bigint nullable (kopecks), minimum_tier code, start_at/end_at, cta_text/cta_url, active, version, created_by text, created_at/updated_at. `offer_campaigns`: id,offer_id,offer_version,audience jsonb,status,requested_by,created_at.

`import_batches`: id,filename,mode,profile jsonb,program_version_id,status,cursor,lease_until,file_path,created_by,created_at,updated_at. `import_rows`: id,batch_id,row_number,payload jsonb,status,errors jsonb,result jsonb,rental_id, UNIQUE(batch_id,row_number).

`outbox_events`: id,event_key unique,event_type,user_id FK nullable,aggregate_id text,account_version bigint,payload jsonb,created_at,expanded_at. `deliveries`: id,event_id FK,active channel `telegram`,target text,status `pending|processing|retry|succeeded|dead|suppressed`,attempts,next_attempt_at,lease_until,lease_token text,last_error,delivered_version bigint,created_at,updated_at, UNIQUE(event_id,channel,target). Core creates outbox only, worker expands deliveries.

`audit_logs`: id,actor_id text,actor_role,action,entity_type,entity_id text,reason,before_data/after_data jsonb,request_id,created_at. `program_settings`: key text PK,value jsonb,updated_at. `analytics_events`: id,event_id unique,user_id,name,entity_id,properties jsonb,created_at. `operational_errors`: id,kind,entity_id,details jsonb,resolved_at,created_at.

All business tables use RLS; no direct anon/authenticated access. Server pool must connect as table owner or BYPASSRLS role. Append-only triggers protect ledger/audit/version records.
