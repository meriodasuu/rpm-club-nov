# Единый автопарк RPM Rent → Club

Автомобили, фотографии, стоимость, порядок, публикация и доступность редактируются только в https://rpmrent.ru/admin/cars. В админке Club автопарк доступен для просмотра, перехода на сайт и проверки времени синхронизации. Изменение автомобилей через API Club запрещено; маршруты и Wiki редактируются как прежде.

Источник — представление `rpm_club_catalog.cars` в PostgreSQL сайта. Оно содержит только данные автомобилей и фотографии, без клиентов, заявок и учётных записей. Отдельная роль `rpm_club_catalog_reader` получает только SELECT этого представления, без прав записи. Пароль находится в `/etc/rpm-club-catalog.env` (0600), передаётся только контейнеру `catalog`. Приложение Club и его база не подключаются к сети базы сайта.

После транзакции изменения `Car`/`CarImage` PostgreSQL отправляет NOTIFY. Контейнер `catalog` читает целый согласованный снимок и атомарно обновляет Club. Дополнительно сверяет каталог каждые 15 секунд и после перезапуска: потеря NOTIFY не теряет данные. Один слушатель защищён advisory lock. Открытые страницы автопарка обновляются каждые 5 секунд, пока вкладка видима.

Связь карточек идёт по ID сайта, а не названию/slug. Повторное чтение не создаёт дубли и не меняет version. Меняется цена — старый расчёт заявки требует пересчёта. Удалённая карточка исчезает из каталога и админки Club, но архивная строка сохраняет ссылки существующих заявок; их суммы и названия не меняются. Скрытые/демо-карточки не видны участникам. Недоступный автомобиль остаётся в каталоге с отключённой заявкой. Ограничение минимального срока проверяется сервером.

Фотографии используют HTTPS-адреса хранилища сайта, без вторых копий. Club показывает обложку и галерею. Отдельной синхронизации бронирований и занятых дат здесь нет: доступность дат подтверждает менеджер, оплата на месте.

Если чтение источника или валидация снимка завершились ошибкой, текущий каталог сохраняется. Если последний успешный снимок старше 2 минут, новые расчёты и заявки на эти автомобили временно блокируются, чтобы не принимать устаревшие цены. Сбой виден по heartbeat контейнера, времени синхронизации в Club и безопасным логам; секреты не выводятся.

## Установка и откат

1. Резервные копии обеих баз. Применить миграцию `20260925100000_site_catalog.sql` только к Club.
2. В БД сайта создать отдельную LOGIN-роль `rpm_club_catalog_reader` без superuser/createdb/createrole, с default_transaction_read_only=on. Применить `deploy/catalog-source.sql` владельцем базы сайта; проверить отсутствие SELECT к исходным таблицам и прав записи.
3. В отдельный приватный env-файл записать `CATALOG_DATABASE_URL=postgresql://rpm_club_catalog_reader:...@rpm-rent-db-1:5432/...`. Порт БД наружу не публиковать.
4. Собрать Club и выполнить `docker compose ... --profile worker up -d --wait app worker telegram catalog`. Профиль catalog подключается к внутренним сетям Club и `rpm-rent_backend`; остальные контейнеры не получают доступ к БД сайта.
5. Проверить начальное количество/фото/цены, далее создание, изменение и удаление скрытой проверочной карточки сайта. Проверить сохранность старых заявок в изолированных интеграционных тестах. В backup Club включён env синхронизации; резервное копирование сайта сохраняет view/триггеры.

Для остановки синхронизации остановить `catalog`; данные не удаляются. Не возвращать редактирование автопарка в двух админках. При откате кода сохранить актуальную Club БД и совместимую добавочную миграцию. Для полного отключения источника отдельно убрать два триггера и схему `rpm_club_catalog` в БД сайта после остановки процесса; не затрагивать таблицы сайта.
