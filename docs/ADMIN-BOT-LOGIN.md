# Вход в админку по ссылке из бота

Реализовано 16 сентября 2026 по уточнённому сценарию пользователя. Вход только по личной ссылке от бота; кнопка входа из Mini App удалена. Привязка Google Authenticator выполняется при первом входе в браузере.

## Сценарий

1. Владелец выдаёт зарегистрированному участнику права через «Добавить админа». Самостоятельно получить права нельзя.
2. Администратор отправляет `/admin` в личный чат с ботом. Достаточно активного зарегистрированного аккаунта с назначенной ролью admin; действующая сессия Mini App не нужна.
3. Обычный пользователь, участник без прав, заблокированный участник или сотрудник с отозванными правами получает ответ «Данная команда недоступна.» без ссылки.
4. Бот отправляет администратору личную ссылку. При первом открытии браузер показывает QR и ручной ключ Google Authenticator. Сессия выдаётся только после проверки шестизначного кода. Существующая подтверждённая настройка сохраняется и повторно не раскрывается.
5. Ссылка действует 10 минут, новая ссылка заменяет предыдущую и сбрасывает только незавершённую настройку аутентификатора. После проверки кода создаётся часовая сессия администратора. Можно открыть ссылку через Telegram на компьютере.
6. При отзыве прав старые ссылки удаляются, сессии отзываются. Права и блокировка участника также проверяются при каждом обращении к защищённым API.

Первый верный код одновременно подтверждает привязку и выполняет вход. URL-фрагмент удаляется из адресной строки при открытии: после обновления страницы нужно заново открыть исходную ссылку из чата или запросить новую.

## Защита

- В базе только SHA-256 хеш случайного 256-битного кода ссылки; TOTP-секрет зашифрован существующим ключом проекта.
- Получатель определяется проверенным отправителем webhook; клиент не может задать чужой Telegram ID. Запрос проверки ссылки защищён проверкой Origin.
- Команда принимается только из личного чата с совпадением отправителя и адресата, webhook защищён секретом. Повторы одного Telegram update не создают повторную отправку при подтверждённом результате.
- Запросы ссылки ограничены тремя в минуту на Telegram ID, проверки входа — десятью в минуту на администратора.
- Только действующая ссылка активного администратора позволяет начать первую настройку Google Authenticator. Подтверждённый фактор нельзя сбросить или получить повторно через ссылку. Новая ссылка аннулирует незавершённый фактор предыдущей ссылки.
- Одноразовый код TOTP нельзя использовать повторно. Ссылка расходуется в одной транзакции с подтверждением фактора и созданием сессии.
- Страница `/admin/access` не загружает сторонние скрипты, удаляет секрет из URL перед первым запросом, запрещает iframe и передачу Referer.
- При сбое Telegram запрос и новая ссылка откатываются; повторная попытка разрешена. Как у любого Telegram sendMessage, потеря ответа после доставки может привести к повторному сообщению; непроведённая ссылка не даст доступа.

## Проверки

Проверка релиза входа 16 сентября: 107 тестов в 18 файлах; TypeScript, ESLint и production build прошли. Последний общий прогон 20 сентября: 110 тестов в 17 файлах, TypeScript, ESLint и сборка Vercel прошли; сценарий входа не менялся. Тесты исключённых из продукта интеграций удалены.

Реальный локальный браузер проверил первую привязку, ввод неверного и верного кода, отсутствие сессии до MFA, переход в панель, запрет повторного использования ссылки, отсутствие секрета в URL и сторонних скриптов. На мобильном размере проверены QR и отсутствие входа в админку на главной и в профиле Mini App. API Telegram в интеграционных тестах подменён. Browser plugin not available: использован Playwright с Edge. Тесты дополнительно проверяют отказ неизвестным, заблокированным и лишённым прав пользователям, замену незавершённой привязки при новой ссылке и сохранение подтверждённого фактора.

Миграция `20260916074532_staff_bot_login_links.sql` применена в облаке. RLS включён; anon/authenticated не имеют доступа к таблице, серверная роль имеет необходимые права. Supabase security advisor: замечаний нет. Фактический приём личного сообщения и ввод кода владельцем после публикации требуют пользовательской проверки.

Прежние маршруты входа через Mini App, запроса ссылки из Mini App и переноса сессии отключены на сервере (410 STAFF_BOT_ONLY), в том числе для старых клиентов. Служебный вход Supabase Auth сохранён без публичного интерфейса. Назначение прав по-прежнему выполняет только владелец.
