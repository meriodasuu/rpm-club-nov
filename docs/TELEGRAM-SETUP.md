# Подключение Telegram

Команда `telegram:setup` настраивает меню и webhook бота. @rpmclub_bot уже подключён; актуальная публикация и порядок обновления описаны в VERCEL-DEPLOYMENT.md.

## Бот и Mini App

1. В [официальном BotFather](https://t.me/BotFather) выполнить `/newbot`. Название: RPM Club; username должен быть свободным и оканчиваться на `bot`. Сохранить выданный токен в `.env.local`, поле `TELEGRAM_BOT_TOKEN`; username без @ — в `TELEGRAM_BOT_USERNAME`. Токен не помещать в Git или клиентский код.
2. Разместить приложение по публичному HTTPS-адресу. Для теста подходит отдельный временный HTTPS-туннель; компьютер, Docker и сервер должны оставаться включёнными. Для постоянной работы нужен постоянно доступный сервер и БД. Публикация в этом этапе не выполнена.
3. На публикуемом экземпляре установить `APP_URL=https://ваш-домен` (без пути), `LOCAL_PREVIEW=0`, `TELEGRAM_WEBHOOK_SECRET` — случайная строка из 32–256 символов A–Z, a–z, 0–9, _ или -. Те же значения должны использовать приложение, worker и команда настройки. Перезапустить сервер после настройки окружения. До публикации отключить локальные preview-входы и отозвать ранее выданные preview-сессии либо использовать отдельную тестовую БД.
4. Проверить `/api/ready` по публичному адресу и отсутствие доступа через `/preview` и `/api/auth/local`. Запуск публичного production-экземпляра — `npm run build`, затем `npm run start`; HTTPS предоставляет хостинг/reverse proxy. Туннель не должен публиковать PostgreSQL.
5. Выполнить `npm run telegram:setup -- --check`. Это только чтение Bot API. Скрипт сверяет username, webhook и кнопку. Для применения: `npm run telegram:setup -- --apply`. Выполняются только setWebhook и setChatMenuButton; затем настройки перечитываются. Очередь Telegram не очищается. Другой уже настроенный webhook не заменяется автоматически; сначала определить правильного бота/назначение.
6. В BotFather: `/mybots` → бот → Bot Settings → Configure Mini App → Enable/Configure Main Mini App. Указать `https://ваш-домен/onboarding`. Названия пунктов могут отличаться между клиентами. Этот шаг включает Main Mini App и ссылки `https://t.me/username?startapp=ref_КОД`; кнопка меню уже настраивается скриптом.
7. Запустить worker по инструкции OPERATIONS.md. `/start` кладёт приветствие в outbox; ответ отправляется worker. Подтверждение контакта обрабатывается непосредственно webhook. Проверить `/start` → открыть → передать собственный номер → принять документы → увидеть счёт. Затем контрольная завершённая и оплаченная аренда → Bonus → сообщение.

Настройки применяются несколькими запросами Bot API, без общей транзакции. Если один запрос не прошёл, запустить `--check`, устранить причину и повторить `--apply`. Ошибки не выводят токен, секрет webhook или полное тело ответа провайдера. Применение настроек не подтверждает реальную доставку контакта/сообщения — для этого нужен пользовательский сценарий.

## Начисление Bonus

Расчёт автоматический после записи completed + paid. Данные могут поступить от менеджера, из operational CSV/XLSX либо через `POST /api/integrations/rentals`. CRM ещё не подключена. Исторический импорт переносит сумму/уровень без нового cashback. Ручные начисления с причиной доступны сотрудникам с соответствующей ролью.

Пример: 287 000 ₽ накопленной суммы + аренда 35 000 ₽ → BLACK (4%) → 1 400 Bonus. Дубликат одной аренды не начисляет Bonus повторно.

Источники: [создание бота](https://core.telegram.org/bots/features#botfather), [Mini Apps](https://core.telegram.org/bots/webapps), [webhook](https://core.telegram.org/bots/api#setwebhook), [кнопка меню](https://core.telegram.org/bots/api#setchatmenubutton). Проверены 12 сентября 2026.
