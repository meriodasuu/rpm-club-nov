# Вход сотрудников по почте и паролю

Адрес: https://club.rpm-rent.ru/admin/login. Google Authenticator не используется. Вход участников в Mini App остаётся через Telegram.

Владелец по-прежнему назначает администраторов по Telegram-нику. Сотрудник отправляет /admin боту @rpmclub_bot и открывает личную ссылку: указывает почту и пароль от 15 до 128 символов. Почта служит логином, регистр и внешние пробелы игнорируются. Отправка писем и SMTP для входа не нужны. Пароль не обрезается и не меняет регистр.

Восстановление: /admin в том же Telegram-аккаунте → новый пароль. Ссылка действует 10 минут, используется один раз, новая отменяет предыдущую. Доступ предоставляется только активному сотруднику с активным связанным пользователем. Ссылка не выдаёт сессию до сохранения пароля. Она позволяет изменить учётные данные, поэтому её нельзя пересылать.

Каждое устройство получает отдельную сессию на час. Новый вход не отзывает другие сессии, выход отзывает только свою. Установка/смена пароля через ссылку и отзыв прав завершают все прежние сессии. Полномочия и Telegram ID сотрудника при настройке пароля сохраняются.

Пароли хранятся только в виде scrypt-хеша с индивидуальной солью: N=65536, r=8, p=2 — профиль 64 MiB из [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#scrypt). Одновременно выполняются максимум две операции хеширования. Ограничения: 5 попыток входа на почту и 60 суммарно в минуту; ключ почты в rate_limits хеширован. Неизвестная почта, неверный пароль и отключённый сотрудник получают одинаковую ошибку. Проверка Origin, HttpOnly/SameSite/Secure cookies и серверные проверки роли сохранены.

Хеши отделены от admin_memberships: таблица staff_password_credentials с RLS доступна runtime-роли; её поля не попадают в ответы списка сотрудников и журнал изменений. Сброс и вход сериализуются по сотруднику; после вычисления хеша вход повторно проверяет текущие учётные данные, чтобы старый пароль не обошёл одновременный сброс.

Установка: backup → остановка старого обработчика Telegram → миграция 20260925170000_staff_passwords.sql → новый образ. Миграция отменяет старые ссылки, ранее защищённые вторым фактором. Старые зашифрованные факторы оставлены в БД для обратимости, исполняемый TOTP-код удалён. Секреты/пароли не включать в Git, логи и отчёты. Первичную установку заданных владельцем учётных данных выполнить адресно для его существующего membership, без создания новых прав.

Откат: остановить Telegram, отменить действующие staff_bot_login_links, вернуть предыдущий образ/compose и запустить обработчики. Добавочная таблица совместима со старым кодом. Прежний вход после отката снова потребует старый TOTP.

Проверки: staff-auth.integration.test.ts — два устройства, выход, роли, блокировка, неправильные пароли, лимиты, Origin; bot-admin-link.integration.test.ts — назначение пароля, сброс, отзыв сессий, уникальность почты, одноразовость, конкурентный обмен, истечение и замена ссылки, доставка только назначенному сотруднику.
